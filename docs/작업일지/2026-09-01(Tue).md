## 세부작업 설명

### 3.1 등록 404 의 정체

"등록이 404 난다"는 신고로 시작. 라우트는 전부 정상(`/events` 200, `/events/new` 200)이었다.

원인은 두 겹이었다.

1. `.env.local` 에 Supabase 섹션이 **통째로 빠져 있었다.** `.env.example` 에는 `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` 항목이 있는데 실제 파일은 Drive 설정에서 끝나 있었다.
2. `supabase/migrations/*.sql` 이 저장소에는 있지만 `supabase/config.toml` 도 없고 프로젝트가 링크된 흔적도 없다. 즉 이 SQL 이 실제 Supabase 에서 실행된 적이 없다.

**PostgREST 는 테이블이 없을 때도 HTTP 404 를 돌려준다.** 그 값이 `postgrest()` 의 `데이터 조회 실패 (404)` 메시지에 그대로 실려 화면에 뜨니, 사용자 입장에서는 "페이지가 없다"로 읽힌다. 여기서 헤맬 이유가 없도록 404 를 별도로 잡아 "테이블을 찾을 수 없습니다. supabase/migrations 의 SQL 을 실행했는지 확인하세요" 로 바꿨다.

### 3.2 검색을 DB 에서 절반만 거르면 결과가 누락된다

처음에는 `listEvents` 가 PostgREST `or=(title.ilike.*q*,body.ilike.*q*,author.ilike.*q*)` 로 거르고, 첨부 파일명·태그는 조회 뒤 JS 로 한 번 더 거르는 구조로 짰다.

작성 직후 설계 결함을 발견했다. **DB 가 제목·본문·작성자로 이미 걸러버리면, 파일명으로만 맞는 글은 애초에 조회 결과에 들어오지 않는다.** 후처리는 좁히기만 할 뿐 넓히지 못한다.

첨부 파일명과 태그는 임베드된 리소스라 같은 `or` 절에 섞을 수 없는 것이 근본 제약이다. 그래서 `EventFilter` 에서 `query` 를 아예 빼고, 검색 전체를 `matchesQuery`(`lib/post-view.ts`) 한 곳으로 모았다. 같은 이유로 연도 필터와 연도 집계(`countByYear`)도 뷰 계층으로 옮겼다 — 연도 칩 개수를 세려면 연도로 거르기 전 전체가 필요하기 때문이다.

정리된 책임: **DB 는 싸게 거를 수 있는 것만(부서·상태·작성자·수정시각), 파생값과 집계가 필요한 것은 뷰 계층.**

### 3.3 좁은 화면 가로 스크롤 — 원인 찾는 데 가장 오래 걸림

모바일(375×812)에서 목록 텍스트가 오른쪽으로 잘려 나갔다. 실측: `clientWidth 375` / `scrollWidth 422`.

처음엔 목록 행을 의심했으나 행의 min-content 는 231 로 멀쩡했다. 섹션을 하나씩 숨겨가며 좁혔다.

| 숨긴 것 | scrollWidth |
|---|---|
| (원본) | 422 |
| 상세 블록 전체 | 375 |
| 첨부 목록만 | 375 |
| 상세 메타 문단만 | 422 |

첨부 목록이 단독 원인이었다. 그런데 첨부 행 자체는 조상 폭을 200px 로 강제하면 166 까지 잘 줄어들었다 — 행이 안 줄어드는 게 아니었다.

진짜 원인은 위쪽이었다. `body` 가 `min-h-full flex flex-col` 이라 자식이 cross-axis stretch 를 받는데, **stretch 는 자식의 min-content 아래로는 내려가지 않는다.** 그래서 안쪽 긴 파일명의 min-content 가 페이지 컨테이너를 통째로 밀어냈다.

가설 4개를 실제로 적용해 측정했다.

| 가설 | 결과 |
|---|---|
| A. 첨부 행 flex 컨테이너에 `min-width:0` | 422 (실패) |
| B. `li` 에 `overflow:hidden` | 422 (실패) |
| C. 페이지 컨테이너에 `width:100%` | **375 (성공)** |
| D. 행 중간 div 에 `width:0` | **375 (성공)** |

D 는 `flex-1 w-0` 관용구로 그 컴포넌트만 고치는 국소 처방이고, C 는 구조적 처방이다. C 를 택했다 — 앞으로 어떤 컴포넌트가 들어와도 같은 문제가 재발하지 않기 때문이다. `ArchiveShell` 의 `main` 에 `min-w-0`(가로 flex 안의 항목이라 `min-width:auto` 가 걸린다), 각 페이지 최상위 컨테이너에 `w-full` 을 넣었다.

덧붙여 목록 행의 보조 정보(첨부수·작성자·날짜)를 좁은 화면에서는 `w-full` 로 줄을 따로 쓰게 했다. 한 줄에 다 밀어 넣으면 이름과 날짜가 붙어 읽기 어렵다.

### 3.4 `formatDate` 가 "-1일 전" 을 출력

프리뷰 데이터로 화면을 보다 발견. `days = Math.floor((now - date) / 86400000)` 가 미래 시각을 받으면 -1 이 되고, `days < 7` 분기를 타고 `-1일 전` 이 그대로 찍혔다.

서버와 드라이브의 시계가 어긋나면 실제로 발생할 수 있다. `Math.max(0, ...)` 로 막았다.

### 3.5 판별 유니온이 좁혀지지 않던 타입 오류

`RevisionsResult` 를 이렇게 잡았더니 `tsc` 가 `FileRevision[] | undefined` 라고 거부했다.

```ts
| { revisions: FileRevision[]; error?: undefined }
| { revisions?: undefined; error: string }
```

`if (result.error)` 는 진위값 검사라, `error: string` 이 빈 문자열일 가능성 때문에 else 분기에서 두 멤버가 모두 남는다. optional undefined 필드는 판별자로 못 쓴다는 뜻이다. `{ ok: true; ... } | { ok: false; ... }` 로 명시적 판별자를 두어 해결.

### 3.6 React Compiler lint 2건

`npm run lint` 가 typecheck 통과 후에 잡아냈다.

- `react-hooks/purity` — `archive/page.tsx` 렌더 중 `Date.now()` 호출. **서버 컴포넌트도 이 규칙의 대상이다.** `lib/events.ts` 의 `daysAgo(days)` 로 옮겨 해결.
- `react-hooks/set-state-in-effect` — `ArchiveShell` 에서 경로 변경을 감시해 서랍을 닫던 effect. 살펴보니 서랍 안 링크가 이미 `onNavigate` 로 닫고 있고, 서랍이 화면을 덮고 있어 다른 경로로 갈 길이 없다. effect 자체가 불필요해서 제거.

### 3.7 그 밖에 손본 것

- **목록 조회 실패 시 툴바까지 사라졌다.** `ErrorState` 를 early return 으로 두었더니 "자료 등록" 버튼도 함께 없어져, DB 가 안 되면 등록 화면으로 갈 길이 막혔다. 툴바는 항상 렌더하고 목록 자리만 오류로 바꾸도록 분리.
- **상태 변경 폼이 읽기 흐름을 끊었다.** 제목 바로 아래 있어서 제목 → 본문 사이를 가로막았다. 페이지 맨 아래로 내리고, 위쪽에는 읽기 전용 배지만 남겼다.
- **첨부 행에 현재 버전이 안 보였다.** 이력을 펼쳐야만 알 수 있었다. 상세에서만 `Promise.all` 로 병렬 조회해 `v3` 를 채웠다(한 건 실패해도 나머지는 표시).
- **`__preview` 임시 라우트가 404.** Next.js App Router 는 `_` 로 시작하는 폴더를 private folder 로 보고 라우팅에서 제외한다. `tmp-preview` 로 바꿔 확인 후 삭제.
